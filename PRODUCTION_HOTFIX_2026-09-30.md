# Production hotfix: расчёты с автошколами

Дата работ: 30.09.2026 (Asia/Irkutsk).

## Что произошло

На production в кабинете руководителя, в разделе итогов и блоке
«Расчёты с автошколами», при нажатии кнопки «Закрыть ... ₽» появлялось
сообщение:

> Добавьте служебный ключ проекта для административных операций

Это был не ключ от кабинета клиента. Сообщение относилось к старому
служебному ключу Supabase:

- `SUPABASE_SECRET_KEY`;
- либо `SUPABASE_SERVICE_ROLE_KEY`.

Добавлять эти ключи обратно на сервер не нужно. Production уже работает с
локальным PostgreSQL, а связь с Supabase была намеренно удалена.

## Причина ошибки

Отчёт «Расчёты с автошколами» уже загружал данные из PostgreSQL, но server
action `settleSourcePaymentsAction` в `src/app/admin/actions.ts` не имел
PostgreSQL-ветки.

При нажатии кнопки обработчик безусловно вызывал `createAdminClient()` и
пытался выполнить операцию через Supabase. Так как Supabase-ключи с production
удалены, действие останавливалось до изменения данных.

До установки hotfix неудачные нажатия на кнопку не изменили деньги или записи:
ошибка возникала до выполнения обновлений.

## Как исправлено

Для `settleSourcePaymentsAction` добавлена отдельная PostgreSQL-ветка.

Теперь при закрытии расчёта сервер:

1. Проверяет, что выбранный источник принадлежит организации руководителя.
2. Повторно получает из PostgreSQL проведённые занятия выбранного инструктора,
   источника и периода.
3. Блокирует найденные записи на время операции.
4. Повторно считает количество занятий и фактический остаток.
5. Сравнивает расчёт с количеством и суммой, показанными руководителю.
6. Если данные успели измениться, ничего не записывает и просит обновить отчёт.
7. Если данные совпадают, одной транзакцией отмечает расчёт закрытым.
8. Записывает событие в журнал аудита.

Hotfix не требует миграции базы данных.

## Что установлено на production

Production-каталог:

```text
/var/www/autoinstructor-calendar-postgres
```

Production-ветка на сервере:

```text
codex-migrate-from-supabase
```

Hotfix был применён поверх `c4d1a73` командой `git cherry-pick 9b6d801`.
Из-за cherry-pick сервер создал свой эквивалентный коммит:

```text
fa6d232 Fix source settlement on PostgreSQL
```

То есть после выкладки текущий `HEAD` production должен быть `fa6d232`.

## Выполненные команды на сервере

```bash
cd /var/www/autoinstructor-calendar-postgres
git fetch origin codex/prod-source-settlement-hotfix
git status --short
git cherry-pick 9b6d801
pnpm build
pm2 restart autoinstructor-postgres-test --update-env
curl -I http://127.0.0.1:3000
```

Результаты:

- `git status --short` перед cherry-pick был пустым;
- cherry-pick прошёл без конфликтов;
- production-сборка завершилась успешно;
- TypeScript завершился без ошибок;
- PM2-процесс `autoinstructor-postgres-test` после перезапуска имеет статус
  `online`;
- `http://127.0.0.1:3000` ответил `HTTP/1.1 200 OK`.

Сайт и домен используют приложение на порту `3000`.

## Предупреждения сборки

Во время `pnpm build` осталось четыре прежних предупреждения Turbopack о
динамическом доступе к локальным файлам в:

- `src/app/uploads/[...path]/route.ts`;
- `src/lib/uploads/legal-documents.ts`.

Они существовали до hotfix, не относятся к расчётам с автошколами и не
помешали сборке.

## Что проверить вручную

В production под руководителем:

1. Открыть «Итоги».
2. Найти «Расчёты с автошколами».
3. Нажать «Закрыть ... ₽» у нужного источника.
4. Подтвердить действие.
5. Убедиться, что сообщение про служебный ключ больше не появляется.
6. Убедиться, что остаток по этому источнику стал равен нулю или уменьшился на
   закрытую сумму.
7. Обновить страницу и повторно проверить цифры.

Нажатие кнопки реально меняет финансовые отметки записей. Проверять её нужно
только тогда, когда руководитель действительно хочет отметить расчёт с
автошколой как закрытый.

## Важно для дальнейшей разработки

Основная локальная рабочая папка содержит отдельные незавершённые изменения по
транзакциям. Они намеренно не были отправлены на production вместе с hotfix.

Перед будущим общим деплоем необходимо перенести hotfix `9b6d801` в актуальную
ветку разработки (через cherry-pick или аккуратное ручное объединение), чтобы
исправление не потерялось при следующей выкладке.

Перед переносом проверить:

```bash
git status --short
git log --oneline --decorate -10
```

Не выполнять слепой `git pull` или общий деплой из основной локальной рабочей
папки, пока незавершённые изменения не проверены и не закоммичены отдельно.

## Безопасный откат hotfix

Если после ручной проверки обнаружится проблема, не использовать
`git reset --hard`. На сервере безопаснее создать обратный коммит:

```bash
cd /var/www/autoinstructor-calendar-postgres
git revert fa6d232
pnpm build
pm2 restart autoinstructor-postgres-test --update-env
```

После отката снова проверить:

```bash
curl -I http://127.0.0.1:3000
```
