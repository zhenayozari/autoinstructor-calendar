Мы подключаемся к PostgreSQL двумя способами: локально через PowerShell и на VPS через SSH.

**Локально, Windows**

1. Перейти в проект:

```powershell
cd "C:\Users\-\Desktop\autoinstructor-calendar"
```

2. Ввести пароль PostgreSQL:

```powershell
$secure = Read-Host "Пароль PostgreSQL" -AsSecureString
$env:PGPASSWORD = [Runtime.InteropServices.Marshal]::PtrToStringBSTR(
  [Runtime.InteropServices.Marshal]::SecureStringToBSTR($secure)
)
```

3. Указать нужную базу:

```powershell
$env:PGHOST = "127.0.0.1"
$env:PGPORT = "5432"
$env:PGUSER = "postgres"
$env:PGDATABASE = "autoinstructor_live_copy_2"
```

4. Проверить подключение:

```powershell
& "D:\Programs\PostgreSQL\17\bin\psql.exe" -c "select current_database(), current_user;"
```

5. Применить новую миграцию:

```powershell
pnpm db:apply-schema -- --schema db/migrations/0016_name_of_migration.sql
```

Миграция меняет структуру базы: добавляет таблицы, поля, индексы. Данные пользователей и записи она сама не переносит.

**На VPS**

1. Подключиться:

```powershell
ssh root@138.16.153.223
```

2. Перейти в новую версию проекта:

```bash
cd /var/www/autoinstructor-calendar-postgres
```

3. Подключить переменные окружения:

```bash
set -a
. ./.env.local
set +a
```

В `.env.local` уже указаны:

```text
APP_BACKEND=postgres
DATABASE_URL=...
APP_SESSION_SECRET=...
STUDENT_ACCESS_SALT=...
UPLOADS_DIR=...
UPLOADS_PUBLIC_PATH=...
```

4. Проверить базу:

```bash
psql "$DATABASE_URL" -c "select current_database(), current_user;"
```

5. Применить новую миграцию:

```bash
pnpm db:apply-schema -- --schema db/migrations/0016_name_of_migration.sql
```

6. Проверить таблицы:

```bash
psql "$DATABASE_URL" -c "\dt public.*"
```

7. Перезапустить приложение после изменений:

```bash
pm2 restart autoinstructor-postgres-test --update-env
```

8. Проверить статус:

```bash
pm2 status
```

Важно: на существующей базе применяем только новые миграции. Старые `0001–0015` повторно запускать не нужно, иначе некоторые команды могут завершиться ошибкой «таблица или столбец уже существует».

Локально у нас три базы:
autoinstructortest
Первая тестовая база, использовалась для ранней проверки миграций.

autoinstructor_live_copy
Первая копия актуальной базы. В ней часть паролей была в старом формате, поэтому вход учеников работал некорректно.

autoinstructor_live_copy_2
Последняя, третья копия из Supabase. Её мы создали заново, перенесли актуальные данные и использовали правильную соль. Именно на ней вход ученика заработал.

**Основной локальный вариант:** autoinstructor_live_copy_2.
**Основная база на VPS:** autoinstructor_prod.
То есть сейчас схема такая:
локальная проверка:
autoinstructor_live_copy_2

боевой сервер:
autoinstructor_prod

резервная старая версия:
Supabase-приложение на старом PM2-процессе
